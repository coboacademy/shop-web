# Upload a Category Image

Uploads or replaces the image associated with a category. The image is stored
on the public disk under `categories/images`.

## Endpoint

| Property | Value |
|---|---|
| Method | `POST` |
| Path | `/api/admin/categories/{category}/image` |
| Authentication | Required; Sanctum bearer token |
| Content type | `multipart/form-data` |
| Response format | `application/json` |

The route is registered in `routes/api.php` in the authenticated admin route
group. It does not declare category-specific permission middleware.

## Path Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `category` | string | Yes | UUID of the category to update. |

## Request Headers

```http
Accept: application/json
Authorization: Bearer <YOUR_TOKEN>
```

Send the request body as `multipart/form-data`; the HTTP client should set its
multipart content type and boundary.

## Request Body

| Field | Type | Required | Constraints | Description |
|---|---|---|---|---|
| `image` | file | Yes | Must be an image in `jpg`, `jpeg`, `png`, or `webp` format; maximum size `5120` KB (5 MB). | Category image file to upload. |

## Example Request

```bash
curl -X POST "<API_BASE_URL>/api/admin/categories/<CATEGORY_ID>/image" \
  -H "Accept: application/json" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -F "image=@/path/to/category-image.jpg"
```

Replace `<API_BASE_URL>` with the API base URL, `<CATEGORY_ID>` with the
category UUID, `<YOUR_TOKEN>` with a valid Sanctum token, and the file path
with the image to upload.

## Successful Response

**HTTP status:** `200 OK`

```json
{
  "status": "success",
  "message": "Category image uploaded successfully.",
  "data": {
    "category": {
      "id": "00000000-0000-4000-8000-000000000001",
      "parent_id": null,
      "name": "Beverages",
      "slug": "beverages",
      "description": null,
      "image": "categories/images/00000000-0000-4000-8000-000000000010.jpg",
      "image_url": "<PUBLIC_IMAGE_URL>",
      "icon": null,
      "icon_url": null,
      "is_active": true,
      "created_at": "2026-11-01T04:00:00.000000Z",
      "updated_at": "2026-11-01T04:15:00.000000Z"
    }
  }
}
```

The IDs, filenames, and timestamps are illustrative. `image` is the stored
public-disk path; `image_url` is generated from that path. The `parent` and
`children` fields are omitted because those relationships are not loaded in
this response.

## Response Fields

| Field | Description |
|---|---|
| `status` | Indicates whether the request succeeded. |
| `message` | Response message. |
| `data.category.id` | Category UUID. |
| `data.category.parent_id` | Parent category UUID, or `null` for a root category. |
| `data.category.name` | Category name. |
| `data.category.slug` | Category slug. |
| `data.category.description` | Category description, or `null`. |
| `data.category.image` | Stored path of the uploaded image. |
| `data.category.image_url` | Public URL for the uploaded image. |
| `data.category.icon` | Stored icon path, or `null`. |
| `data.category.icon_url` | Public URL for the icon, or `null`. |
| `data.category.is_active` | Whether the category is active. |
| `data.category.created_at` | Category creation timestamp. |
| `data.category.updated_at` | Last category update timestamp. |

## Error Responses

### 401 Unauthenticated

Returned when the request does not include a valid authenticated session or
bearer token.

```json
{
  "status": "error",
  "message": "Unauthenticated."
}
```

### 404 Not Found

Returned when `<CATEGORY_ID>` does not identify an existing, non-deleted
category.

```json
{
  "status": "error",
  "message": "Resource not found."
}
```

### 422 Unprocessable Content

Returned when `image` is missing, is not a valid image, uses a format other
than `jpg`, `jpeg`, `png`, or `webp`, or exceeds 5120 KB.

```json
{
  "status": "error",
  "message": "Validation failed",
  "errors": {
    "image": [
      "The image field is required."
    ]
  }
}
```

## Behavior Notes

- The new image is uploaded and its path is persisted before the previously
  stored image is removed. If upload or persistence fails, the existing image
  and database path are left unchanged.
- If removing the old image fails after the new path is persisted, the API
  returns a server error; the category points to the new image and the old
  file may remain on disk.
- Stored filenames are generated by the storage service; clients do not choose
  the destination filename.
- The uploaded file is stored on the `public` disk in `categories/images`.
- Configure the public storage URL and storage link for browser access to
  `image_url`.
