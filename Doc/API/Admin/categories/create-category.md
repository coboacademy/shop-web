# Create an Admin Category

Creates a category with an optional parent category. The API generates a unique
slug from the submitted name.

## Endpoint

| Property | Value |
|---|---|
| Method | `POST` |
| Path | `/api/admin/categories` |
| Authentication | Required; Sanctum bearer token |
| Response format | `application/json` |

The route is registered in `routes/api.php` in the authenticated admin route
group. It does not declare category-specific permission middleware.

## Request Headers

```http
Accept: application/json
Authorization: Bearer <YOUR_TOKEN>
Content-Type: application/json
```

## Request Body

| Field | Type | Required | Constraints | Description |
|---|---|---|---|---|
| `name` | string | Yes | 2–150 characters | Category name. Used to generate the category slug. |
| `parent_id` | UUID or `null` | No | Must identify an existing category when provided. | Parent category UUID. Omit or set to `null` to create a root category. |
| `description` | string or `null` | No | Must be a string when provided. | Optional category description. |

`slug` is generated by the API and is not accepted in the request body. If the
generated slug already exists, the API appends an incrementing numeric suffix
such as `-1`.

## Example Request

```bash
curl -X POST "<API_BASE_URL>/api/admin/categories" \
  -H "Accept: application/json" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Coffee",
    "parent_id": "00000000-0000-4000-8000-000000000001",
    "description": "Coffee and coffee-based drinks."
  }'
```

Replace `<API_BASE_URL>` with the API base URL, `<YOUR_TOKEN>` with a valid
Sanctum token, and `parent_id` with an existing category UUID. Example values
are illustrative.

## Successful Response

**HTTP status:** `201 Created`

```json
{
  "status": "success",
  "message": "Category created successfully.",
  "data": {
    "category": {
      "id": "00000000-0000-4000-8000-000000000002",
      "parent_id": "00000000-0000-4000-8000-000000000001",
      "name": "Coffee",
      "slug": "coffee",
      "description": "Coffee and coffee-based drinks.",
      "image": null,
      "image_url": null,
      "icon": null,
      "icon_url": null,
      "is_active": true,
      "created_at": "2026-11-01T04:00:00.000000Z",
      "updated_at": "2026-11-01T04:00:00.000000Z"
    }
  }
}
```

The IDs and timestamp are illustrative. `image` and `icon` are initially
`null`; their URL fields are also `null`. The `parent` and `children` fields
are omitted because those relationships are not loaded in this response.
`is_active` defaults to `true`.

## Response Fields

| Field | Description |
|---|---|
| `status` | Indicates whether the request succeeded. |
| `message` | Response message. |
| `data.category.id` | Created category UUID. |
| `data.category.parent_id` | Parent category UUID, or `null` for a root category. |
| `data.category.name` | Category name. |
| `data.category.slug` | Unique slug generated from the name. |
| `data.category.description` | Category description, or `null`. |
| `data.category.image` | Stored image path, initially `null`. |
| `data.category.image_url` | Public image URL, initially `null`. |
| `data.category.icon` | Stored icon path, initially `null`. |
| `data.category.icon_url` | Public icon URL, initially `null`. |
| `data.category.is_active` | Whether the category is active; defaults to `true`. |
| `data.category.created_at` | Category creation timestamp. |
| `data.category.updated_at` | Last category update timestamp. |

## Error Responses

### 401 Unauthenticated

Returned when the request does not include a valid authenticated session or
bearer token.

```json
{
  "status": "error",
  "message": "Unauthenticated."
}
```

### 422 Unprocessable Content

Returned when request validation fails, for example if `name` is missing or
shorter than 2 characters, or if `parent_id` is not a UUID for an existing
category.

```json
{
  "status": "error",
  "message": "Validation failed",
  "errors": {
    "name": [
      "The name field is required."
    ]
  }
}
```

## Behavior Notes

- The parent category must exist and must not be soft-deleted.
- Root categories are created when `parent_id` is omitted or `null`.
- The generated slug is made unique across categories.
- No request field controls `is_active`; newly created categories use the
  database default of `true`.
- The endpoint does not accept image or icon uploads in this request.
