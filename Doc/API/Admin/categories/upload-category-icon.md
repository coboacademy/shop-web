# Upload a Category Icon

Uploads or replaces the icon associated with a category. The file is stored on
the public disk under `categories/icons`.

## Endpoint

| Property | Value |
|---|---|
| Method | `POST` |
| Path | `/api/admin/categories/{category}/icon` |
| Authentication | Required; Sanctum bearer token |
| Content type | `multipart/form-data` |
| Response format | `application/json` |

The route is registered in `routes/api.php` in the authenticated admin route
group. It does not declare category-specific permission middleware.

## Path Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `category` | string | Yes | UUID of the category to update. |

## Request Headers

```http
Accept: application/json
Authorization: Bearer <YOUR_TOKEN>
```

Send the request body as `multipart/form-data`; the HTTP client should set its
multipart content type and boundary.

## Request Body

| Field | Type | Required | Constraints | Description |
|---|---|---|---|---|
| `icon` | file | Yes | Must be a file with `svg`, `png`, or `webp` extension; maximum size `2048` KB (2 MB). | Category icon file to upload. |

## Example Request

```bash
curl -X POST "<API_BASE_URL>/api/admin/categories/<CATEGORY_ID>/icon" \
  -H "Accept: application/json" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -F "icon=@/path/to/category-icon.svg"
```

Replace `<API_BASE_URL>` with the API base URL, `<CATEGORY_ID>` with the
category UUID, `<YOUR_TOKEN>` with a valid Sanctum token, and the file path
with the icon to upload.

## Successful Response

**HTTP status:** `200 OK`

```json
{
  "status": "success",
  "message": "Category icon uploaded successfully.",
  "data": {
    "category": {
      "id": "00000000-0000-4000-8000-000000000001",
      "parent_id": null,
      "name": "Beverages",
      "slug": "beverages",
      "description": null,
      "image": null,
      "image_url": null,
      "icon": "categories/icons/00000000-0000-4000-8000-000000000010.svg",
      "icon_url": "<PUBLIC_ICON_URL>",
      "is_active": true,
      "created_at": "2026-11-01T04:00:00.000000Z",
      "updated_at": "2026-11-01T04:25:00.000000Z"
    }
  }
}
```

The IDs, filenames, and timestamps are illustrative. `icon` is the stored
public-disk path; `icon_url` is generated from that path. The `parent` and
`children` fields are omitted because those relationships are not loaded in
this response.

## Response Fields

| Field | Description |
|---|---|
| `status` | Indicates whether the request succeeded. |
| `message` | Response message. |
| `data.category.id` | Category UUID. |
| `data.category.parent_id` | Parent category UUID, or `null` for a root category. |
| `data.category.name` | Category name. |
| `data.category.slug` | Category slug. |
| `data.category.description` | Category description, or `null`. |
| `data.category.image` | Stored image path, or `null`. |
| `data.category.image_url` | Public image URL, or `null`. |
| `data.category.icon` | Stored path of the uploaded icon. |
| `data.category.icon_url` | Public URL for the uploaded icon. |
| `data.category.is_active` | Whether the category is active. |
| `data.category.created_at` | Category creation timestamp. |
| `data.category.updated_at` | Last category update timestamp. |

## Error Responses

### 401 Unauthenticated

Returned when the request does not include a valid authenticated session or
bearer token.

```json
{
  "status": "error",
  "message": "Unauthenticated."
}
```

### 404 Not Found

Returned when `<CATEGORY_ID>` does not identify an existing, non-deleted
category.

```json
{
  "status": "error",
  "message": "Resource not found."
}
```

### 422 Unprocessable Content

Returned when `icon` is missing, is not a file, uses a format other than
`svg`, `png`, or `webp`, or exceeds 2048 KB.

```json
{
  "status": "error",
  "message": "Validation failed",
  "errors": {
    "icon": [
      "The icon field is required."
    ]
  }
}
```

## Behavior Notes

- The new icon is uploaded and its path is persisted before the previously
  stored icon is removed. If upload or persistence fails, the existing icon
  and database path are left unchanged.
- If removing the old icon fails after the new path is persisted, the API
  returns a server error; the category points to the new icon and the old file
  may remain on disk.
- Stored filenames are generated by the storage service; clients do not choose
  the destination filename.
- The uploaded file is stored on the `public` disk in `categories/icons`.
- Configure the public storage URL and storage link for browser access to
  `icon_url`.
