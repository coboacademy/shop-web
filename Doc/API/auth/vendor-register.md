# Register a Vendor Account

Creates a user account with the Vendor role and a pending vendor profile.

## Endpoint

| Property | Value |
|---|---|
| Method | `POST` |
| Path | `/api/admin/vendors/register` |
| Route name | `api.admin.vendors.register` |
| Authentication | Not required; guest route |
| Content-Type | `application/json` |
| Response format | `application/json` |

The route is registered in `routes/api.php`.

### Request headers

```http
Accept: application/json
Content-Type: application/json
```

## Request Body

| Field | Type | Required | Validation Rules |
|---|---|---|---|
| `name` | string | Yes | Maximum 255 characters |
| `email` | string | Yes | Valid email address, maximum 255 characters, and unique among users |
| `password` | string | Yes | At least 6 characters; must match `password_confirmation` |
| `password_confirmation` | string | Yes | Must exactly match `password` |
| `business_name` | string | Yes | 3–100 characters |
| `phone` | string | No | Maximum 30 characters |
| `description` | string | No | Maximum 1000 characters |
| `website` | string | No | Must be a valid URL, maximum 255 characters |
| `country` | string | No | Maximum 100 characters |
| `province` | string | No | Maximum 100 characters |
| `city` | string | No | Maximum 100 characters |
| `address` | string | No | Maximum 255 characters |

Optional fields may be omitted or set to `null`.

```json
  "message": "Vendor registered successfully.",
  "data": {
    "id": "00000000-0000-4000-8000-000000000000",
    "business_name": "Example Market",
    "slug": "example-market",
    "email": "alex@example.com",
    "phone": "+1-555-0100",
    "description": "An illustrative vendor profile.",
    "website": "https://example.com",
    "country": "Example Country",
    "province": "Example Province",
    "city": "Example City",
    "address": "123 Example Street",
    "logo": null,
    "cover_image": null,
    "status": "pending",
    "verified_at": null,
    "created_at": "2026-10-30T09:00:00.000000Z"
  }

```

The vendor ID and slug are generated by the application. The slug is based on the business name and adjusted if needed to remain unique. The response data is serialized by the `VendorResource`.

This endpoint does not return a bearer token or send an email verification OTP. Account login and email-verification requirements are handled separately.

## Error Responses

### 422 Unprocessable Content

Returned when request validation fails. Validation errors include a field-specific `errors` object. Examples include:

- `Name is required.`
- `This email already exists.`
- `Password must be at least 6 characters.`
- `Password confirmation does not match.`
- `Email format is invalid.`

The application returns JSON validation errors for API requests with the `status`, `message`, and `errors` fields.

### 500 Internal Server Error

If vendor registration fails, the endpoint returns:

```json
{
  "success": false,
  "message": "Vendor registration failed."
}
```

When application debug mode is enabled, the response may contain the exception message instead.

## Registration Behavior

- The route is public and applies the `guest` middleware.
- Registration creates a pending user and a pending vendor profile in a database transaction; a failure rolls back the transaction.
- The new user is assigned the `Vendor` role. If that role does not exist, the controller creates it before assignment.
- Vendor registration also assigns the `vendor.create`, `vendor.update`, and `vendor.delete` permissions.
- The vendor profile email is set to the account email.
- No route-specific throttle middleware is declared for this endpoint.
- Vendor approval and any subsequent email verification are not performed by this endpoint.
